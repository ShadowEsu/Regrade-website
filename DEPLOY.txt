Quick deploy (GitHub Pages + optional custom domain)

1) Set your waitlist inbox
   - Open site-config.js in this folder.
   - Replace YOUR_EMAIL@example.com with the address where you want signup emails.

1b) See every signup (recommended for static hosting)
   - Create a free account at https://web3forms.com and copy your access key.
   - Paste it into site-config.js as web3formsAccessKey.
   - Submissions appear in the Web3Forms dashboard and in your email.

1c) Local / test log in the browser
   - Open waitlist-data.html on the same site (footer link "Waitlist log").
   - It lists signups stored in that browser only (useful when you test yourself).
   - For all visitors’ signups, use Web3Forms (step 1b).

2) Push this folder to a GitHub repository (root should contain index.html).

3) Enable Pages
   - Repo → Settings → Pages → Build and deployment → Source: Deploy from a branch.
   - Branch: main (or master), folder: / (root). Save.
   - After a minute, the site is at https://<username>.github.io/<repo-name>/

4) Custom domain (optional)
   - In the same Pages settings, enter your domain under Custom domain.
   - At your DNS provider, add the records GitHub shows (usually A records for apex, or CNAME for www).
   - GitHub may create a CNAME file automatically; commit it when prompted.

5) Project site vs user site
   - User/org site: repo named <username>.github.io → site is https://<username>.github.io/
   - Project site: any other repo name → URL includes the repo name as a path (scripts here use relative URLs, so both work).
